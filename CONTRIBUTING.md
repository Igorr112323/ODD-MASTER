# Как работать с каркасом

Правила коммитов: Conventional Commits, тип на английском, описание на русском (`feat(core): генератор треугольного носителя`). Каждый коммит собирается: `bash scripts/verify.sh`.

## Добавить знак через конфиг (MVP-30)

1. Откройте `config/catalog/signs.poc.json` и скопируйте блок-шаблон (последний элемент массива с `"_template": true`).
2. Укажите `number` (например `«3.24»`), `name` (из табл. А.1–А.8), `shape`, `sizeTableId` (Д.2…Д.9), `group`, семантические цвета и слои.
3. Проставьте `normRef` (`doc`, `clause`, `table`, `figure`) и `verification`. Статус `StudentVerified` ставит только человек после сверки с официальным текстом ГОСТ.
4. Если точной геометрии нет — ставьте `null` и заведите `GOST-NNN` в `docs/VERIFICATION_QUEUE.md`; для отрисовки допустим `Placeholder`, но тогда выход помечается «ЧЕРНОВИК».
5. Запустите `dotnet test OddMaster.sln`. Тест конфигов проверит наличие `normRef`/`verification`, тест каталога — разрешение размеров.
6. Обновите галерею: `dotnet run --project src/OddMaster.Demo -- signs`, затем закоммитьте `docs/demo/signs/`.

## Как сверить нормативные данные

См. `docs/VERIFICATION_QUEUE.md`: для каждого `GOST-NNN` указано, что сверить, где в стандарте и как пометить `StudentVerified`. До сверки статус менять нельзя.

## Чего не делать

- Не вставлять числа из ГОСТ в код: только в `config/`.
- Не добавлять ссылки на `Multicad.*` вне `src/OddMaster.NanoCAD/`.
- Не удалять и не ослаблять тесты ради зелёной сборки; не глушить предупреждения без записи в ADR.
- Не добавлять DLL SDK, PDF ГОСТ, LICENSE и большие бинарники.
