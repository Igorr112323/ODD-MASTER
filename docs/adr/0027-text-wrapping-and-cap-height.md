# ADR-0027: Кегль один на блок, перенос по словам, высота прописных отдельно от кегля (CR-17)

- **Статус:** принято (сессия 03).
- **Дата:** 2026-10-29.
- **Связано:** CR-17, E-054…E-057, GOST-002.

## Контекст

`TextEngine.Layout` вписывал строку в прямоугольник **уменьшением кегля**. В узкой колонке
ведомости («Примечание», 64 мм, шапка «Номер знака по ГОСТ Р 52290-2024», 55 мм) это давало
кегль 1,7 мм — текст формально внутри, но нечитаем. Вторая проблема: `LayoutBlock` считал высоту
по одной строке, поэтому трёхстрочная шапка и двухстрочный баннер вылезали за свой прямоугольник.

Третья, отдельная: в САПР `TEXT`/`MTEXT` задаёт **высоту прописных**, а в SVG `font-size` — кегль
(em). Одно и то же число давало разный видимый размер в двух приёмниках.

## Решение

1. `TextEngine.LayoutWrapped(text, boxWidth, boxHeight, metrics, center)` — greedy-перенос по словам,
   **один кегль на все строки**, каждая строка ≤ ширины, слова не разрываются, если влезают.
   Кегль только уменьшается (монотонная итерация, ≤ 8 шагов) — результат детерминирован.
2. Порог читаемости `minCapHeightMm` в `config/typography/fonts.json` (2,5 мм, условное значение,
   GOST-002). Ниже порога текст **переносится**, а не мельчает; деление слова по символам — только
   когда слово шире колонки при пороге (иначе «Наименовани|е»).
3. `LayoutBlock` делит высоту на `lines.Count * (1 + LineGapRatio)` — блок целиком влезает в рамку.
4. `TableCell.Lines` — единственный носитель текста ячейки; `StatementDxfWriter` пишет один `TEXT`
   на строку.
5. Кегль модели (`HeightMm`) и высота прописных (`CapHeightMm = HeightMm · capHeightRatio`)
   разделены: DXF получает `CapHeightMm`, SVG — `HeightMm`.

## Альтернативы

- Уменьшать кегль до нуля (как было): нечитаемо, и это маскирует ошибку формы.
- `MTEXT` с автоматическим переносом: R12 его не знает, nanoCAD рисует по-своему — недетерминированно.
- Перенос по символам всегда: рвёт слова без нужды.

## Последствия

Плюсы: шапка таблицы читается (cap ≥ 2,5 мм), баннер внутри поля, одинаковый вид в SVG и DXF.
Минусы: форма ведомости стала чувствительна к ширине колонок — при смене шрифта строки могут
переразбиться; ширины колонок подобраны под DejaVu Sans Bold (GOST-002 открыт).
