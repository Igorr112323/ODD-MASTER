# ADR-0026: Кайма знака — залитая полоса между двумя контурами (CR-16)

- **Статус:** принято (сессия 03).
- **Дата:** 2026-10-29.
- **Связано:** CR-16, ADR-0025, GOST-001.

## Контекст

До сессии 03 внутренняя кайма рисовалась как обводка контура толщиной `innerBorderWidthMm`.
В SVG это работало, в DXF — нет: у сущности `LINE`/`POLYLINE` нет ширины, и красная кайма
исчезала. Это обнаружилось только потому, что появился второй приёмник (DXF) и независимая
перечитка `ezdxf`. Это настоящая находка «по-САПРовски», а не косметика.

## Решение

Кайма — **геометрическая полоса**: поле знака до каймы заливается цветом каймы, поверх него —
поле после каймы цветом поля. В модели это два слоя: `InnerBorder` (контур, смещённый внутрь на
ширину наружной каймы) и `Field` (смещение на наружную + внутреннюю). Оба залитые (`Filled = true`),
`StrokeWidthMm = 0`. Ширина полосы равна `(Bounds(inner).Width − Bounds(field).Width) / 2`.

## Альтернативы

- Толстая обводка контура: в DXF нет, в nanoCAD зависит от `LWPOLYLINE` constant width и стиля — риск.
- Штриховка (`HATCH`) между контурами: в R12 недоступна нормально, в nanoCAD требует объектов-ассоциаций.

## Последствия

Плюсы: одинаковый результат в любом приёмнике, у которого есть заливка; ширина проверяема числом;
инвариант «кайма = полоса» (M14-B01) ловит регрессию. Минусы: две заливки вместо одной обводки —
на 41 знаке это +41 сущность в DXF; порядок отрисовки теперь важен (кайма → поле → состав → текст).
