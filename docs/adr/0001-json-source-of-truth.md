# ADR-0001: JSON в git — источник истины нормативных данных

- **Статус:** см. «Последствия».
- **Дата:** 2026-10-27.

## Контекст

Нормативка меняется, и её правки должны быть видимы в ревью. Нужна история изменений без бинарных файлов.

## Решение

Все нормативные значения (номенклатура, размеры, каймы, параметры, правила контроля, карта замен) лежат в `config/*.json`. У каждого файла есть `normRef` и `verification`. Код не содержит чисел из ГОСТ. JSON Schema в `config/schema/` описывают форму.

## Альтернативы

SQLite как основное хранилище (бинарные диффы, не видно в PR); константы в C# (правка требует пересборки); CSV (нет вложенных структур).

## Последствия

Плюсы: диффы, ревью, проверка в тестах. Минусы: валидация на старте приложения, ручная сверка. SQLite остаётся возможным кэшем позже. Статус: принято.
