# ADR-0030: Триггеры CI, страж состава решения и workflow регенерации

- **Статус:** принято (сессия 03).
- **Дата:** 2026-10-29.
- **Связано:** CR-21, CR-26.1, ADR-0029.

## Контекст

1. Проект `OddMaster.Render.Dxf.Tests` был добавлен в `OddMaster.sln` без строк
   `ProjectConfigurationPlatforms`. `dotnet build/test OddMaster.sln` его молча пропускал: 22 теста
   DXF не выполнялись в CI ни разу. «Тесты проходят локально» означало прямой запуск проекта.
2. Каждый коммит запускал CI дважды: `push: branches-ignore: [main]` и `pull_request` дают разные
   ref, поэтому `concurrency` их не схлопывал. При этом коммиты в `main` после мёржа CI не проверял.
3. Агент не может запускать официальный .NET 8, поэтому эталоны нельзя пересобрать локально
   без нарушения ADR-0029.

## Решение

- **CR-21.** Проект добавлен в конфигурации решения. Введён страж `scripts/check_solution_tests.py`:
  каждый проект из `tests/` обязан быть в решении и иметь строки конфигураций; при передаче лога
  `dotnet test` число тестовых сборок в логе обязано совпасть с числом тестовых проектов.
  Шаг в CI: `python3 scripts/check_solution_tests.py --log test.log`. Страж краснеет, если проект
  выпал из решения (проверено на специально испорченной копии `.sln`).
- **CR-26.1.** `on: push: branches: [main]`, `pull_request`, `workflow_dispatch`;
  `concurrency.group: ci-${{ github.event.pull_request.number || github.ref }}` — один прогон на PR.
- **Регенерация.** Workflow `Regenerate` запускается меткой `[regen]` в сообщении коммита
  (`workflow_dispatch` недоступен, пока файла нет в `main`). Он собирает официальным SDK 8, гоняет
  демо и тесты с `ODD_UPDATE_GOLDEN=1`, перечитывает DXF через ezdxf и коммитит изменения.
  Защита от цикла: коммиты с сообщением `chore(artifacts)` не запускают workflow.

## Последствия

Плюсы: тесты DXF выполняются в CI (три сборки в логе), двойных прогонов нет, `main` проверяется,
эталоны обновляются официальным SDK. Минусы: регенерация требует пуша с меткой (два коммита);
коммит бота делает PR-голову «первым участником», и GitHub может требовать подтверждения прогона —
в таком случае достаточно пуша обычного коммита.
