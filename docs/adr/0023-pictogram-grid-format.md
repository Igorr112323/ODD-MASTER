# ADR-0023: Формат пиктограмм в клетках масштабной сетки прил. Б

- **Статус:** принято (сессия 02, P2).
- **Дата:** 2026-10-28.

## Контекст

MVP-30 требует ~41 пиктограммы. Рисовать их в миллиметрах нельзя: у знаков разные типоразмеры,
а источник — растровая масштабная сетка прил. Б. Нужен формат, который студент сможет заполнить
трассировкой Inkscape, не пересчитывая координаты вручную.

## Решение

Формат JSON (`config/schema/pictogram.schema.json`): `id`, `sign`, `status`, `source`, `grid`, `layers`.
`grid.cellsAcross` — сколько клеток сетки покрывает размер носителя `grid.spans` (A, B, D или H);
начало координат в центре, ось Y вверх. Слои содержат `polygon`, `polyline`, `circle`, `text`
в клетках. Статусы: `Placeholder` → `StudentTranscribed` → `StudentVerified`.

Конвейер: `odd-tools pictogram import` (Дуглас–Пекер, допуск в клетках) и
`odd-tools pictogram overlay` (растр страницы + полупрозрачный знак). Проверяется `selftest`
на синтетической стрелке.

## Альтернативы

- Хранить SVG-файлы как есть (нет привязки к размеру носителя, нельзя масштабировать по Д.2–Д.9).
- Хранить абсолютные мм для каждого типоразмера (умножает объём данных в 4 раза).
- Растровые спрайты (не вектор, плохо для САПР).

## Последствия

Плюсы: одна пиктограмма на все типоразмеры, оцифровка ускоряется, статус виден в данных.
Минусы: кривые Безье пока не импортируются (нужно переводить в отрезки); реальные пиктограммы
ГОСТ не оцифрованы — в репозитории только заглушки (GOST-019). ADR-0021 ограничивает точность:
±2 мм в натуре для схемы, производственные допуски п. 3.15 не применяются.
